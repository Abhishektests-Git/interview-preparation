A

The Map — start from zero

Four words everyone mixes up, sorted out once and for all.

01

AI vs ML vs Deep Learning vs GenAI

Four boxes, one inside the other — like Russian dolls.
Foundation

Think of it as a family. AI is the whole family. Inside it lives Machine Learning. Inside that, Deep Learning. And the youngest, loudest member is Generative AI.

🎬 The nested boxes — press play
🤖 Artificial Intelligence (AI)

Any machine doing a task that looks “smart” — chess apps, face unlock, spam filters. It does not have to learn anything.

📈 Machine Learning (ML)

AI that learns patterns from data instead of following hand-written rules.

🧠 Deep Learning (DL)

ML using very large neural networks with many layers — great at images, voice and language.

✨ Generative AI (GenAI)

Deep learning that creates new content — text, images, code, music — instead of just classifying things.

✍️ Rule-based (old way)

A spam filter written by hand:

IF email contains “FREE MONEY” → spam
IF sender is unknown AND has 5 links → spam

Breaks the moment spammers change one word. You do all the thinking.

🌱 Learned (ML way)

Show the system 10,000 spam and 10,000 real emails. It figures out its own rules — words, patterns, sender behaviour.

Spammers change tactics? Feed it new examples and it adapts. The machine does the pattern-finding.

💡 Remember: AI ⊃ ML ⊃ Deep Learning ⊃ GenAI — each one is a smaller, more specific idea inside the bigger one.
02

What is an LLM — deeply, word by word

Large Language Model. Three words, three ideas.
Core concept

An LLM is autocomplete that read the whole library. Your phone keyboard suggests the next word after seeing a few words. An LLM does the same trick — after “reading” most of the internet, and with billions of dials tuned by that reading.

LARGE

Billions of parameters (adjustable dials). More dials = it can capture more patterns of language.

LANGUAGE

It works on text — words, sentences, code, tables. Everything becomes text in, text out.

MODEL

A trained mathematical system. Not a person, not a database — a huge pattern-matching machine.

🎛️ Parameters = dials — why size matters

7B model — 7 billion dials. Fast, cheap, good at simple tasks.

70B model — 70 billion dials. Slower, pricier, noticeably smarter.

A neural network in plain words: layers of tiny units. Each unit takes numbers in, turns its dials (weights), and passes numbers on. During training, every dial gets nudged millions of times until the guesses get good.

🔍

NOT a search engine

Google finds pages that exist. An LLM generates new sentences that never existed before.

🗄️

NOT a database

A database stores exact facts you can look up. An LLM stores patterns — so it can sound right and still be wrong (see §13).

🧩

It stores patterns, not facts

It learned how language and ideas connect — like a student who understood the subject, not one who memorised an answer key.

💡 Remember: LLM = a giant pattern machine for language, tuned by billions of dials — it generates, it doesn't look up.
B

How an LLM actually works

The engine room — five ideas that explain almost everything else.

03

Tokens & tokenization

The model doesn't read words. It reads tokens — chunks with ID numbers.
Engine · 1 of 5

Before anything clever happens, your sentence is chopped into tokens and each token becomes a number. The model only ever sees numbers — never letters.

🎬 Watch a sentence split
TestingID 9642
isID 318
funID 933
forID 329
testID 1287
ersID 480

Notice “testers” split into test + ers. Common chunks get one token; rare words get split into pieces. Punctuation and spaces are tokens too.

📏

The 4-character rule

Roughly 4 characters ≈ 1 token in English. 100 words ≈ 130 tokens. This is how API usage (and cost) is counted.

🔢

Why numbers only?

Maths needs numbers. Token IDs are just the entry point — next, each ID becomes a rich list of numbers called an embedding (§4).

💡 Remember: Text → tokens → numbers. The model never sees your actual words, only token IDs.
04

Embeddings — meaning as numbers

Every token becomes a list of numbers that captures its meaning.
Engine · 2 of 5

An embedding is a token written as a long list of numbers (say, 1,536 numbers) — like coordinates on a giant map of meaning. Words with similar meanings land close together on that map.

🗺️ The word map — similar words cluster
king 👑 queen 👸 man woman cat 🐱 dog 🐶 apple 🍎 banana 🍌

The famous party trick: king − man + woman ≈ queen. The maths literally works, because “royalty” and “gender” are directions on the map. Cosine similarity in one line: a score for how close two meanings point — near 1 = very similar, near 0 = unrelated.

💡 Remember: Embeddings turn meaning into distance — close on the map = close in meaning.
05

Next-token prediction — the core loop

This one loop is the entire secret. Everything else is support staff.
Engine · 3 of 5

The model does exactly one job, over and over: read everything so far → guess the probabilities for the next token → pick one → add it → repeat. Paragraphs, poems and Java code all come out of this loop.

🎬 Building a sentence, one token at a time
The cat sat on the ___
mat
62%
floor
21%
roof
9%
moon
3%

It doesn't “know” the answer — it ranks what's likely. Pick “mat”, append it, and run the loop again for the next token.

💡 Remember: An LLM writes by predicting one likely token at a time — fluency comes from the loop, not from understanding like a human.
06

Attention & Transformers

How the model knows which words matter to which other words.
Engine · 4 of 5

Read this: “The animal didn't cross the street because it was tired.” What does “it” mean — animal or street? You knew instantly. Attention is the mechanism that lets the model do the same: every word looks at every other word and decides how much each one matters.

🎬 Attention arcs — thick = strong link

“it” pays strong attention to “animal” and only weak attention to “street” — so the model reads “it” as the animal. This happens for every word pair, in every layer, all at once.

🏗️

Transformer

The architecture (overall design) built on attention. ChatGPT, Claude, Gemini — all Transformers. The “T” in GPT literally stands for Transformer.

⚡

Why it won

Older models read word-by-word in order, like a person with a tiny bookmark. Transformers read the whole sentence at once — faster to train, and far better at long-range links like “it → animal”.

💡 Remember: Attention lets every word weigh every other word; the Transformer is the design built on that idea.
07

Context window — short-term memory

The model can only “see” a limited amount of text at once.
Engine · 5 of 5

The context window is the model's working memory — the chunk of conversation it can see right now, measured in tokens (modern models: tens of thousands to over a million). It is not permanent memory.

🎬 When the chat outgrows the window
👋 “Hi, I'm Abhishek”“I test pension software”“Explain joins…”“Now a login test…”“One more question…”

Keep chatting past the limit and the oldest blocks fall out — the model genuinely can't see them anymore. That's why a long chat “forgets” what you said at the start.

🪟 Context = temporary

Lives only for this conversation. Close the chat, it's gone. Like RAM in a computer.

🎛️ Weights = baked-in

Knowledge frozen in during training. Like a printed textbook — present in every chat, but never updated by chatting.

💡 Remember: Context window = what the model can see now; weights = what it learned during training. Different things.
C

How an LLM is made

Study once (training), get coached (fine-tuning), then answer forever (inference).

08

Training (pretraining) — the study phase

Done once. Slow, expensive, and it's where all the “knowledge” comes from.
Making · 1 of 3

Imagine a student reading books, websites and code for years — except after every sentence, they must guess the next word, check the real one, and adjust. That guessing-and-correcting, repeated trillions of times, is pretraining. Every correction nudges the dials (weights) a tiny bit.

🎬 Data in, dials tuned
📚 Books🌐 Websites💻 Code📰 Articles💬 Conversations

Weights filling up with patterns…

Guess → compare → nudge dials → guess again. No human writes the rules; the patterns settle into the weights by themselves.

🐢

Slow & expensive

Weeks to months on thousands of GPUs, costing crores. That's why only a few companies train frontier models from scratch.

1️⃣

Done once

After pretraining you get a base model — brilliant at continuing text, but not yet a helpful assistant. That comes next (§9).

💡 Remember: Pretraining = read everything, guess the next token, fix your dials — trillions of times, exactly once.
09

Fine-tuning + RLHF — the coaching phase

A base model can complete text. Coaching turns it into an assistant.
Making · 2 of 3

Fine-tuning is extra training on a smaller, high-quality set of examples — like a graduate doing a focused internship after a general degree.

📝

SFT — learn from good examples

Supervised Fine-Tuning: show the model thousands of ideal question → answer pairs (“when asked this, answer like this”). It learns the assistant style: helpful, structured, polite.

🏆

RLHF — learn from human preference

Reinforcement Learning from Human Feedback: humans are shown two answers and pick the better one, thousands of times. The model learns which answers people prefer — clearer, safer, more honest — not just which are likely.

🏷️ LoRA — the budget-friendly fine-tune

LoRA (Low-Rank Adaptation): instead of retraining all billions of dials, you train only a small add-on module — like adding a sticky-note layer of corrections on top of a textbook instead of reprinting the book. Result: most of the benefit, a fraction of the cost, and you can keep different add-ons for different tasks.

💡 Remember: SFT teaches by example, RLHF teaches by preference, LoRA does fine-tuning cheaply with a small add-on.
10

Inference — the answering phase

Training happens once. Inference happens every time anyone asks anything.
Making · 3 of 3

Inference simply means using the trained model. The dials are frozen now — no learning happens while you chat. Your question goes in, and the next-token loop (§5) runs until the answer is complete.

D

Controlling the output

Two dials you actually control: randomness, and how you ask.

11

Sampling & Temperature — try it yourself

Drag the slider. Watch the probabilities — and the personality — change.
Hands-on ⭐

The model gives probabilities (§5). Sampling is how the next token gets picked from them, and temperature controls how wild that pick is. Low = safe and repetitive. High = creative and risky.

🎛️ Interactive — “The best testing tool is ___”

Likely completion:

The best testing tool is Selenium — widely used for web automation.

Same model, same question — only the temperature changed. Facts and code usually want low temperature; stories and brainstorming want higher.

🎯 Greedy

Always pick the single highest-probability token. Most predictable — temperature 0 behaves like this. Great for facts, boring for stories.

🔝 Top-k

Pick randomly, but only from the k best candidates (e.g. top 40). The long tail of nonsense words is cut off first.

📊 Top-p (nucleus)

Pick from the smallest set whose probabilities add up to p (e.g. 0.9). The set grows or shrinks depending on how confident the model is.

💡 Remember: Temperature tunes randomness — 0 for facts, ~0.7 balanced, 1+ for creativity. Top-k and top-p limit where the randomness can roam.
12

Prompt engineering — the practical skill

The model is fixed. The prompt is yours. This is the skill you will actually use daily.
Practical ⭐

A prompt is simply everything you send the model. Prompt engineering = asking well. Same model, better prompt, dramatically better answer — as any tester who's written a good vs bad bug report already knows.

⚙️ System prompt — standing instructions“You are an expert SDET. Answer in simple English with examples. If unsure, say so.” — set once, applies to the whole conversation, like a test plan.
👤 User prompt — this question“Give me 5 negative test cases for a login page.” — changes every turn, like a single test case.
0️⃣

Zero-shot — just ask

No examples, direct question. “Classify this review as positive or negative.” Works when the task is common and clear.

3️⃣

Few-shot — show, then ask

Give 2–3 examples first, then your real input. The model copies the pattern.

“Great app!” → Positive“Worst update ever” → Negative“Crashes on login” → ?
🪜

Chain-of-thought

Add “think step by step.” The model reasons in the open, one step at a time — and multi-step problems (maths, logic, debugging) get far more accurate.

🎭

Role prompting

“You are an expert tester reviewing a pension app…” A role focuses the vocabulary, depth and tone of the answer.

❌ Vague prompt

“Write test cases for login.”

You get 5 generic lines you've seen a hundred times. The model had to guess everything: platform? fields? depth? format?

✅ Specific prompt

“You are an SDET. For a banking login page with username, password and OTP: give 8 test cases — 3 positive, 5 negative — in a table with ID, steps, expected result. Include one SQL-injection attempt.”

Role + context + count + split + format + edge case. The answer is usable as-is.

🏆 The three golden rules
1 · Be specific 🎯2 · Give examples 📌3 · Give context 🧾
💡 Remember: System prompt = standing orders, user prompt = today's question. Specific + examples + context = good answers.

Making it reliable & useful

Fixing the big flaw, then giving the model books, tools, and a job.

13

Hallucination — confident, fluent, wrong

The most important limitation to understand — and to say in interviews.
Must-know ⚠️

A hallucination is when the model states something false with full confidence — an invented date, a fake law, a book that doesn't exist. It isn't lying; it has no concept of truth. It only knows what text sounds likely (§5), and false text can sound exactly as likely as true text.

“The Taj Mahal was built in 1857 by Shah Jahan's grandson.”
(Fluent. Confident. Completely invented.)

SOUNDS RIGHT ≠ IS RIGHT

Why it happens

The loop rewards plausible, not verified. Gaps in training data get filled with the most likely-sounding continuation.

How to reduce it

Use RAG (§14) so answers come from real documents · ask for sources · lower the temperature · and verify anything that matters — exactly like verifying a bug before raising it.

💡 Remember: The model predicts likely text, it doesn't check truth — so confident ≠ correct. Always verify.

Retrieval-Augmented Generation: let the model look things up before answering.
Must-know ⭐

The model can't know your company's private documents — they weren't in its training. RAG fixes that: before answering, the system searches your documents, finds the most relevant pieces, and hands them to the model along with the question. Closed-book memory becomes an open-book exam.

15

RAG vs Fine-tuning — which one, when?

The comparison interviewers love most. Learn this cold.
Interview favourite ⭐
📖

RAG — the open book

What changes: nothing in the model — you give it documents at question time.
Knowledge: update a document, answers update instantly.
Sources: yes — answers can cite where they came from.
Best for: facts, private/latest documents, company Q&A.

🏋️

Fine-tuning — the coaching

What changes: the model's behaviour itself (§9).
Knowledge: baked into weights — updating means retraining.
Sources: no — it just “knows”, can't show its work.
Best for: a fixed style, tone, format or specialised task.

Question to askAnswer
“It doesn't know our new policy.”RAG — it's a knowledge problem.
“It knows the facts but replies too casually for a bank.”Fine-tuning — it's a behaviour problem.
“We need both — our documents, in our voice.”Both together — very common in real products.
💡 Remember: Need new knowledge → RAG. Need new behaviour → fine-tuning. Often, both.

Agents — from answering to doing

Give the model a goal, tools, and a loop — and it works on its own.
Capability

A chatbot answers once. An agent keeps going: it plans the steps, acts with tools, checks the result, and repeats until the goal is done — like a junior teammate, not a search box.

🔁 The agent loop — goal: “Book the cheapest morning train to Delhi under ₹1,500”

Agent = LLM + Tools + Loop + Memory

💡 Remember: Agent = a model with a goal, tools in its hands, and a plan–act–check loop until the job is finished.

19

Calling an LLM from code (API)

How your Selenium script — or any program — would talk to a model.
For developers

Programs don't open a chat window. They send an API request: a list of messages (system + user, §12) over the internet to the model's service, and get text back. That's it — like calling any REST API you already know from API testing.

📤 You send

{ "model": "a-large-model", "messages": [ { "role": "system", "content": "You are an expert tester." }, { "role": "user", "content": "2 test cases for login?" } ] }

📥 You receive

{ "answer": "1) Valid login succeeds… 2) Wrong password shows an error and stays on the login page…", "tokens_used": 148 }

🌊 Streaming = the answer arrives token by token, like someone typing — that's why ChatGPT appears to “type”. Same answer, delivered live instead of all at once.

💡 Remember: API = send a message list, get text back, pay per token. Streaming just delivers it as it's generated.

Models, limits & judging

20

The model landscape

Names you'll hear in interviews — and what actually differs between them.
Landscape
🔒

Closed / company models

GPT (OpenAI) · Claude (Anthropic) · Gemini (Google). You use them via API, you can't download them. Usually the most capable, always the easiest to start with.

🔓

Open models

Llama (Meta) and others like Mistral. Downloadable — run them on your own machines, full control and privacy, but you handle the hosting and they're often a step behind the frontier.

⚖️ The size trade-off — every model choice is this balance
🪶 Small model

Fast ⚡ · Cheap 💰 · Runs on a laptop
Good for simple, high-volume tasks

⚖️
🦣 Large model

Smarter 🧠 · Better reasoning
Slower and pricier per token

“Parameters” (§2) is the size dial: 7B in a small model vs hundreds of billions in the biggest. Bigger is not always better — it's a cost/quality trade, like choosing a test suite's scope.

💡 Remember: Closed = rent the best brain by API. Open = own a slightly smaller brain outright. Size trades speed and cost against smarts.
21

Limits of LLMs — the honest list

Saying these clearly in an interview makes you sound senior, not negative.
Honesty ⭐
📅

No real-time knowledge

Training stopped at a cut-off date. It doesn't know yesterday's news or your new policy — unless RAG or a tool supplies it.

🎭

Can be confidently wrong

Hallucination (§13). Fluency is not evidence of truth.

🧮

No reasoning guarantee

It produces reasoning-shaped text. Long maths, logic and counting can quietly go wrong mid-answer.

🪟

Forgets beyond the window

Anything outside the context window (§7) simply doesn't exist for it.

🪙

Cost per token

Every token in and out is metered. Long prompts and long answers cost real money at scale.

⚖️

Bias from data

It learned from human text — including human biases, which can leak into answers.

💡 Remember: Frozen knowledge, fluent mistakes, finite memory, metered cost — design around all four.
22

Evaluation — judging without an answer key

For normal software, expected result is fixed. For AI, it isn't. So how do you judge?
Judging

Ask a chatbot “Explain photosynthesis” ten times and you get ten different, mostly-good answers. There is no single right string to compare against — so evaluation changes from matching to judging.

👩‍⚖️

Human review

People score answers for correctness, helpfulness and tone. Slow and costly — but still the gold standard.

📋

Scoring rubrics

A checklist: Is it factually right? Does it answer the question? Any unsafe content? Score 1–5 on each — turns opinion into something repeatable.

🎯

Meaning, not exact words

Compare the meaning of the answer with the expected meaning (embeddings, §4, can even automate the similarity check).

🧪

Test sets of questions

A fixed bank of questions with known-good answers, run after every model or prompt change — regression testing, AI edition (§23).

💡 Remember: Evaluating AI is testing without a fixed expected result — you judge meaning and quality against a rubric, not an exact string.

23

AI in testing + Testing AI apps

Two different jobs. Interviewers are impressed when you separate them.
Your edge ⭐

🅰️ AI helping testers (AI in testing)

📝

Test-case generation

Feed a requirement, get draft test cases — positive, negative, boundary — in seconds. You review and sharpen them; the blank page disappears.

💡

Explaining code & errors

Paste a stack trace or an unfamiliar framework method; get a plain-English explanation. A patient senior, on demand.

🩹

Self-healing locators

A button's ID changes and your Selenium locator breaks. AI-assisted tools find the element another way (text, position, nearby labels) and heal the script instead of failing the suite.

🐞

Drafting bug reports

Turn rough notes and a screenshot into a clean report — steps, expected vs actual, severity suggestion.

🅱️ Testing AI apps (testing of AI)

🎲

Non-determinism

Same question, different answer each run. Exact-match assertions are useless — you assert on meaning, keywords and constraints instead.

🕵️

Hallucination testing

Deliberately ask about things that don't exist (“our 1998 refund policy”) and check the app admits ignorance instead of inventing an answer.

⌨️

Prompt regression

Someone edits the system prompt — does quality silently drop? Run the fixed question bank (§22) after every prompt change.

🛡️

Safety & edge inputs

Abusive prompts, attempts to leak the system prompt, other customers' data in RAG results — a whole new test surface.

📌 Honest framing for interviews: present this section as awareness you're actively learning — “I'm exploring how AI fits into testing workflows” — not as project experience. That honesty is itself a strength.

💡 Remember: AI in testing makes testers faster; testing of AI means judging meaning, not matching strings.

“Say it in an interview”

Model answers — one calm paragraph each. Tap to open, practise out loud.
Perform 🎤
❓ What is an LLM?

“An LLM is a Large Language Model — a neural network with billions of parameters, trained on massive amounts of text to predict the next token. Because it was trained at that scale, it can generate fluent text, answer questions, summarise and write code. It doesn't store facts like a database; it stores patterns of language, which is also why it can sometimes be confidently wrong.”

❓ What is Generative AI?

“Generative AI is the branch of AI that creates new content instead of just analysing existing data. Traditional AI classifies — spam or not spam. GenAI generates — it writes the email, draws the image, drafts the code. LLMs like GPT and Claude are the text side of GenAI.”

❓ How does ChatGPT work?

“In three stages. First, pretraining: the model reads huge amounts of text and learns to predict the next token, which tunes billions of weights. Second, fine-tuning with human feedback — SFT and RLHF — teaches it to be a helpful assistant rather than just a text completer. Third, when I chat with it, that's inference: my text is tokenised, the model predicts the answer token by token using attention over the context window, and temperature controls how creative the picks are.”

❓ RAG vs fine-tuning?

“RAG gives the model knowledge at question time — you search your documents and pass the relevant chunks with the question, so answers are current and can cite sources. Fine-tuning changes the model's behaviour through extra training — style, tone, format. My rule of thumb: if the problem is missing knowledge, use RAG; if it's wrong behaviour, fine-tune; real products often use both.”

❓ What is hallucination, and how do you handle it?

“Hallucination is when the model produces fluent, confident text that is factually wrong. It happens because the model predicts what sounds likely, not what is verified. In practice you handle it by grounding answers with RAG, asking for sources, keeping temperature low for factual tasks, and verifying critical outputs — never treating fluency as proof.”

❓ How would you test a chatbot?

“Differently from deterministic software, because the same question can give different valid answers — so I test meaning and constraints, not exact strings. I'd build a fixed question bank with rubrics for correctness and tone, test hallucination with questions about things that don't exist, test the prompts themselves with regression runs after any prompt change, and cover safety cases — prompt leakage and cross-customer data in RAG results. I'm exploring this area actively; it's where my testing background meets GenAI.”
