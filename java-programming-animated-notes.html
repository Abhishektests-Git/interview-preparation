Section 1

Introduction to Java

Java was created by James Gosling and team at Sun Microsystems (released 1995, now owned by Oracle). Its promise: Write Once, Run Anywhere — the same compiled program runs on Windows, Linux or Mac because the JVM (Java Virtual Machine) sits between your code and the operating system.

C / C++PythonJava
ExecutionCompiled to machine code per OSInterpreted, line by lineCompiled to bytecode, run by JVM
SpeedFastestSlowerFast (JIT compiler)
TypingStaticDynamicStatic — errors caught early
PointersYesNoNo — safer memory handling

Java is object-oriented, platform-independent, robust (automatic garbage collection, no pointers) and multithreaded. That is why it powers enterprise systems — and most Selenium test frameworks.

▶ Watch: how “Write Once, Run Anywhere” works

1 · WriteYou write Hello.java once.
2 · Compilejavac turns it into Hello.class — bytecode, not machine code.
3 · Run anywhereEach OS has its own JVM that reads the same bytecode.
4 · OutputSame result on Windows, Linux and Mac.
RememberJava code compiles to bytecode, and the JVM — not the OS — runs it. That one layer is the whole secret of platform independence.
Section 2

JDK, JRE and JVM

  • JVM — the engine that executes bytecode. Abstract machine, no physical form.
  • JRE — JVM + core libraries. Enough to run a Java program.
  • JDK — JRE + development tools (javac, java, javadoc, debugger). Needed to write and compile programs.

So: JDK ⊃ JRE ⊃ JVM — each one contains the next.

▶ Watch: the compile-and-run workflow

Hello.javaSource code you write.
javacThe compiler (from the JDK) checks and compiles it.
Hello.classBytecode — platform-neutral.
JVM + JITInterprets bytecode and hot-spots it to fast native code.
OutputProgram runs on the OS.
RememberDevelopers install the JDK; end users only need the JRE; the JVM inside does the actual running.
Section 3

Structure of a Java Program

Every standalone Java program starts at one exact doorway: the main method. The file name must match the public class name.

public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
  • public — JVM must be able to call it from outside.
  • static — JVM calls it without creating an object first.
  • void — it returns nothing.
  • String[] args — command-line arguments land here.

▶ Watch: the JVM find its starting point

1 · LoadJVM loads the Hello class.
2 · LookIt searches for public static void main(String[] args) — exactly that signature.
3 · EnterFound — execution begins at main, no object needed.
4 · PrintSystem.out.println writes “Hello, Java!”.
RememberIf main is not public static void main(String[] args), the JVM simply cannot find the starting point.

Section 5

Input and Output

Three common ways to read input: Scanner (easiest, parses numbers for you), BufferedReader (faster, reads lines as text), and formatted output with printf.

import java.util.Scanner;

Scanner sc = new Scanner(System.in);
System.out.print("Name: ");
String name = sc.nextLine();
System.out.print("Age: ");
int age = sc.nextInt();
System.out.printf("Name: %s, Age: %d%n", name, age);  // %s=String, %d=int, %n=new line

Output: Name: Aarav, Age: 27 — the Name/Age demo from the carousel.

▶ Watch: the Name/Age demo run

PromptProgram prints “Name: ” and waits.
nextLine()User types Aarav — stored as a String.
nextInt()User types 27 — Scanner converts it to an int.
printf%s and %d slots fill in → “Name: Aarav, Age: 27”.
RememberScanner parses types for you (nextInt, nextDouble); BufferedReader only gives you Strings, which you convert yourself.

Section 7

Conditional Statements

int marks = 82;
String grade;
if (marks >= 90)      grade = "A";
else if (marks >= 75) grade = "B";   // 82 lands here
else                 grade = "C";

// Same decision, one line — the ternary operator:
String result = (marks >= 40) ? "Pass" : "Fail";

// switch — best when testing one value against many fixed options:
switch (grade) {
    case "A" -> System.out.println("Excellent");
    case "B" -> System.out.println("Good");
    default  -> System.out.println("Keep going");
}

▶ Watch: the grade example decide

marks = 82Start with the value.
82 >= 90?No — move to the next branch.
82 >= 75?Yes — grade = "B", chain stops.
Ternary check82 >= 40 → result = "Pass".
RememberAn if-else chain stops at the first true branch — order your conditions from most specific to most general.
Section 8

Loops and Repetition

  • for — when you know how many times: counting, arrays.
  • while — when you stop on a condition: reading until end of data.
  • do-while — runs at least once, then checks: menus, retry prompts.
  • break exits the loop; continue skips to the next round.
int sum = 0;
for (int i = 1; i <= 5; i++) {
    sum += i;               // 1, 3, 6, 10, 15
}
System.out.println(sum);    // 15

▶ Watch: the sum build up, round by round

i = 1sum = 0 + 1 = 1
i = 2sum = 1 + 2 = 3
i = 3sum = 3 + 3 = 6
i = 4sum = 6 + 4 = 10
i = 5sum = 10 + 5 = 15 ✓
Rememberfor = known count, while = unknown count, do-while = at least once. Pick by the question, not by habit.
Section 9

Arrays — and Two-Dimensional Arrays

An array holds many values of one type under one name, addressed by index — and indexing starts at 0.

int[] marks = {78, 85, 92, 66, 74};
int total = 0;
for (int m : marks) total += m;          // enhanced for — no index needed
double avg = (double) total / marks.length; // 79.0

int[][] jagged = { {1, 2}, {3, 4, 5} };  // rows can have different lengths
Arrays.sort(marks);                     // java.util.Arrays: sort, toString, binarySearch…

A 2D array is an array of arrays — think rows and columns, like a marks sheet or a test-data table. You walk it with nested loops: outer loop for rows, inner loop for columns.

int[][] sheet = { {80, 90}, {70, 60} };
for (int r = 0; r < sheet.length; r++)
    for (int c = 0; c < sheet[r].length; c++)
        System.out.print(sheet[r][c] + " ");

▶ Watch: reading a 2D array, cell by cell

[0][0] = 80Row 0, column 0.
[0][1] = 90Inner loop finishes row 0.
[1][0] = 70Outer loop moves to row 1.
[1][1] = 60Done — row by row, left to right.
Remembermarks.length is a field (no brackets) for arrays — but name.length() is a method for Strings. Mixing them up is a classic exam trap.
Section 10

Strings — and a Palindrome Practice

Strings in Java are immutable: once created, the text never changes. Every “modification” quietly creates a new String. That is why repeated joining in a loop should use StringBuilder — one mutable object, no pile of copies.

String a = "Policy";
String b = "Policy";
a == b;              // true here (same pool object) — but never rely on it
a.equals(b);        // true — THIS is how you compare text
new String("Policy") == a;  // false! Different object, same text. equals() still true.

StringBuilder sb = new StringBuilder("madam");
String rev = sb.reverse().toString();      // "madam"
boolean palindrome = "madam".equals(rev);  // true

▶ Watch: palindrome check with StringBuilder.reverse()

Original"madam"
ReverseStringBuilder flips it → "madam"
Compare with equals()Both texts match…
ResultPalindrome ✓ (try "level" ✓, "policy" ✗)
Remember== asks “same object?”; equals() asks “same text?”. For Strings, you almost always mean equals().
Section 11

Methods and Parameter Passing

Java is always pass-by-value: a method receives a copy. For primitives the copy is the number itself; for objects the copy is the reference — so the method can change the object's fields, but cannot swap your variable to a different object.

static int premium(int cover) { return cover / 100; }
static int premium(int cover, int riders) { return cover / 100 + riders * 500; } // overloading: same name, different parameters

static int total(int... amounts) {          // varargs: any number of ints, arrives as an array
    int s = 0; for (int a : amounts) s += a; return s;
}
total(100, 200, 300);  // 600

static int fact(int n) {              // recursion: a method that calls itself
    return (n <= 1) ? 1 : n * fact(n - 1);   // fact(5) = 120 — base case stops the chain
}

▶ Watch: recursion unwind fact(5)

Call downfact(5) → 5 × fact(4) → 4 × fact(3) → 3 × fact(2)…
Base casefact(1) = 1 — the chain stops here.
Multiply back up2 × 1 = 2, 3 × 2 = 6, 4 × 6 = 24…
Answer5 × 24 = 120 ✓
RememberOverloading = same name, different parameter list, decided at compile time. Every recursive method needs a base case, or it recurses until StackOverflowError.
Section 12

Classes and Objects

A class is the blueprint; an object is a house built from it. Fields hold state, methods hold behaviour, and a constructor sets the starting state — it has the class's name and no return type.

public class Student {
    private String name;          // private = encapsulated, no direct outside access
    private int marks;

    public Student(String name, int marks) {   // constructor
        this.name = name;  this.marks = marks;
    }
    public String getName() { return name; }        // getter
    public void setMarks(int m) { if (m >= 0 && m <= 100) marks = m; } // setter validates
}
Student s = new Student("Aarav", 82);

Section 13

The Four Principles of OOP

EncapsulationHide the data, expose controlled methods. Private fields + getters/setters.
InheritanceChild class reuses and extends a parent. extends, IS-A relationship.
PolymorphismOne name, many forms — overloading and overriding.
AbstractionShow what it does, hide how. Abstract classes and interfaces.

A Page Object class is all four at once: locators stay private (encapsulation), pages extend a BasePage (inheritance), the same click() helper behaves per page (polymorphism), and test code calls loginPage.login(user, pass) without knowing the steps inside (abstraction).

▶ Watch: one login, four principles

AbstractionTest calls login(user, pass) — steps stay hidden.
PolymorphismThe same helper calls behave correctly on every page.
RememberEncapsulation hides data, Abstraction hides complexity — same family, different hiding.
Section 14

Inheritance and Composition

class Policy {
    protected int sumAssured;
    void showStatus() { System.out.println("Inforce"); }
}
class TermPolicy extends Policy {        // IS-A: a TermPolicy IS-A Policy
    TermPolicy(int cover) { super(); this.sumAssured = cover; }  // super() calls the parent constructor, must be first line
}

Composition is the HAS-A alternative: a class holds an object of another class as a field — a Car has an Engine, a Policy has a Nominee. Prefer composition when there is no true IS-A link: it is looser, easier to change, and avoids deep inheritance chains.

▶ Watch: creating a TermPolicy

new TermPolicy(500000)Child constructor starts.
super() firstThe Policy part is built before anything else.
Then the childsumAssured is set to the cover passed in.
Inherited freeshowStatus() from Policy already works on it.
RememberAsk “IS-A or HAS-A?” first. Inheritance for IS-A, composition for HAS-A — and Java allows only one extends, but unlimited composition.

Section 17

Packages and Access Modifiers

A package is a folder for related classes — it prevents name clashes and controls access. The package line is the first line of the file, and the folder structure must match it.

package com.aevi.tests;                 // this file lives in com/aevi/tests/

import org.testng.annotations.Test;     // borrow one class…
import java.util.*;                     // …or a whole package

public class PolicyTest {
    @Test public void verifyPremium() { /* … */ }
}

Protected, once more, carefully: a protected member is visible inside its own package to everyone, and outside the package only to subclasses — which is why framework base classes (driver setup, waits) declare shared members protected: every test class that extends the base can use them, nothing else can.

▶ Watch: a test class find everything it needs

package linePolicyTest declares its address: com.aevi.tests.
import linesTestNG's @Test is borrowed into the file.
protected at workIt extends the base class, so protected driver setup is visible.
RunverifyPremium() executes with everything resolved.
RememberPackage = address, import = directions, access modifier = who is allowed through the door.

Final section

Interview Answers — In Your Own Words

Short model answers framed the way an SDET actually uses Java. Practise saying them out loud.

1. Why is Java platform-independent?

“Java source compiles to bytecode, not machine code. Any operating system with a JVM can run that same bytecode, so I write and compile once and the program — or my test suite — runs on Windows, Linux or a CI machine unchanged.”

2. == vs equals() — when does it matter in testing?

“== compares object references; equals() compares content. When I read text from a web page with getText() and compare it with expected data, I always use equals() — == can fail even when the visible text is identical, because the two Strings are different objects.”

3. Where do you use OOP in your Selenium framework?

“All four principles, daily. Encapsulation: Page Object classes keep locators private and expose only actions like login(). Inheritance: all test classes extend a BaseTest that holds driver setup and teardown. Polymorphism: WebDriver driver = new ChromeDriver() — the interface reference lets me switch browsers without changing test code. Abstraction: tests call business-level methods and never see the click-and-type steps inside.”

4. Overloading vs overriding — one example each.

“Overloading is compile-time: my utility class has enterText(field, String) and enterText(field, int) — the compiler picks by argument type. Overriding is runtime: a subclass redefines a parent method, like a page class overriding a common wait behaviour. Overriding is also what makes the WebDriver interface work across browsers.”

5. How do you handle lots of test data in Java?

“Small fixed sets go in arrays or a TestNG DataProvider as Object[][]. For readable, key-based data I use collections — List for ordered rows, Map for field-name-to-value pairs from a policy record, Set when duplicates must be rejected. Strings from the application are compared with equals(), and anything I build repeatedly in a loop uses StringBuilder.”

6. Abstract class or interface — how do you choose?

“If classes share state and common code, an abstract class — my BasePage holds the driver and shared waits. If unrelated classes only share a capability, an interface — WebDriver itself is an interface, which is why ChromeDriver, FirefoxDriver and EdgeDriver can all be used through one reference type. A class extends one class but can implement many interfaces.”

RememberInterviewers for SDET roles don't want textbook Java — they want Java with a framework attached. Always land the answer on a line of code you have actually written.
